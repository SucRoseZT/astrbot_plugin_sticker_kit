# 蔗糖的表情包小屋~

独立表情包库插件：WebUI 面板上传、LLM 视觉自动打标、快速通道一次回复即配图、可选 QQ 表情格式。

## 功能

- **WebUI 管理面板**：上传 / 删除 / 编辑标注 / 下载原图 / 状态筛选（失败一键重试），面板顶部显示实际存储路径
- **LLM 视觉自动打标**：接入任意 OpenAI 兼容视觉 API。强制受控情绪词表 + 「一个主情绪 + 至多一个次情绪 + 置信度」，杜绝小模型凑数式乱标；手改过的字段不会被重打标覆盖
- **多模型降级**：可勾选多个 AstrBot 提供商当候选，主模型被限流/报错时自动换下一个；图片只读一次，换模型不额外耗时
- **偷别人的表情包**：别人发表情包时（QQ 表情，或当图片发出来的表情图），AI 可以问一句要不要收进库；也可以由群里任何人直接喊「偷这张」；还能开「主动偷」让 AI 看到有意思的自己收（`steal_proactive`）。收下的图默认进「待审核」，你点了允许才参与检索，也可以开开关让它直接进库
- **按天看库**：库存列表按入库日期折叠分组，默认只展开今天，点表头展开/收起；每张图标明来源（手动添加 / 批量导入 / 偷的）
- **检索可解释**：主情绪权重最高、名称权重最低，每个字段只取最佳命中（不再叠加计分），低于门槛或领先不足就只发文字，不会硬塞一张不相干的图
- **批量导入友好**：固定 worker 池 + 全局最小请求间隔 + 429/503 全队列冷却 + 指数退避重试；打标前自动缩图，上百张一次导入不会打崩也不会卡面板
- **快速通道配图**：AI 回复末尾输出 `<sticker>` 标签即自动本地检索配图，一次回复就带图，省 token 速度快
- **AI 工具调用**：`sticker_pick` / `sticker_search` / `sticker_list`，支持会话冷却、发送概率、全局写锁防刷屏

## 上传方式（桌面端 / 浏览器通用）

1. 点击上传区选择文件（可多选）
2. 截图后直接 `Ctrl+V` 粘贴
3. 粘贴本地文件夹路径，一键批量导入（递归扫描、内容去重、单次上限 500 张）
4. 在浏览器中打开面板（面板内有入口），支持拖拽图片 / 文件夹到页面任意位置
5. 浏览器登录 WebUI 后也可从侧边栏直接进入面板

> 桌面端 Launcher（Tauri）会在窗口层拦截系统拖拽，属宿主限制，面板内已提供浏览器打开入口与文件夹导入兜底。

## token 开销

`sticker_search` / `sticker_list` 的结果会作为工具调用记录**永久留在对话历史里**，之后每一轮请求都要重新计费。所以这两条路径按档位裁剪：

| 配置 | 单次调用 | 与最省相比 |
|---|---|---|
| `sticker_search` 标准 + 6 条（v1.6.1 默认） | ≈665 token | — |
| `sticker_search` 标准 + 4 条 | ≈483 token | −27% |
| `sticker_search` 精简 + 4 条 | **≈318 token** | **−52%** |
| `sticker_list` 标准 + 每页 20 条 | ≈1435 token | — |
| `sticker_list` 精简 + 每页 10 条 | **≈271 token** | **−81%** |

**快速通道完全不产生这部分开销。** 它由 AI 直接输出 `<sticker>{"query":"..."}</sticker>`，插件在本地检索，没有工具调用、没有返回记录进历史。所以每次对话都省 token 的做法是：让 AI 走快速通道，只在确实需要精确指定某一张时才调 `sticker_search`。

协议本身（system_prompt 里那段）每轮都要付，约 200~285 token。`protocol_mode` 关掉就没有，但 AI 也就不会主动配图了。

## system_prompt 不会存在模型那边

LLM 接口是**无状态**的：模型不会"记住"上一轮给过它什么。每一次请求都要把完整的 `messages`（含 system）重新发一遍、重新计费，差别只在于很多服务商有 prompt cache 能打折，但**长度本身是躲不掉的**。

所以任何塞进 system_prompt 的东西都是「每轮固定成本」。本插件的两段（实测 44 张库存）：

| 内容 | 每轮约 | 说明 |
|---|---|---|
| 协议本体 | ≈207 token | 告诉 AI 怎么写 `<sticker>` 标签，`protocol_mode` 关掉就没有 |
| 库存概览（可选） | 0 ~ `brief_budget` | 一行「库存里有哪些情绪 + 各多少张」，让 AI 不用先检索就知道有什么。默认 100 预算实测 88 |

库存概览在注入时会**自动删掉协议里那段 32 词的内置词表**（既然下面已经列了真实库存，再说一遍纯属重复，省 77 token），所以开 100 预算的实际净增只有**约 11 token**。

库存 500 张、100 个分类时，概览也不会无限长 —— 按 `brief_budget` 截断，张数少的分类先被丢掉。面板顶部会显示「约 88 / 100 token」和「还有 N 个分类没放进去」。

「注入分类」页支持三档：**自动**（按张数挑到预算用完）、**手动**（自己勾）、**关闭**。手动勾选超出预算时会直接提示「当前库存已达到预算上限！请去设置里自行调整」，不会悄悄截断你选的内容。

## 配图频率怎么调

频率由四层叠加决定，从软到硬：

1. **档位**（`sticker_frequency`）：只影响提示词里对 AI 的倾向描述，是"软"引导。选「关闭」则完全不注入协议，AI 不会主动配图。
2. **概率**（`send_probability`）：AI 已经写出标签后，再按概率决定发不发。`0.9` 意味着每十次吞掉一次，想要稳定就设 `1.0`。
3. **冷却**（`send_cooldown_seconds`）：同一会话两次发图的最小间隔，`30` 意味着半分钟内第二张一定发不出去。
4. **点名豁免**（`named_request_bypass`）：用户消息命中关键词时，第 2、3 层直接跳过——要就发得出来。

只想让 AI 少发一点 → 降档位；发现它写了标签却没图 → 先把概率调到 1.0、冷却调到 0 再观察。
`/sticker freq 较多` 可在聊天里直接切档位，`/sticker status` 会显示当前档位、概率、冷却以及最近一次协议注入和标签命中的时间，用来判断是"模型没写标签"还是"插件没注入"。

## 投递方式

`delivery_mode` 对两条路径都生效：

- **快速通道**（AI 自己在回复末尾写标签）：`separate_after` 时正文先发，正文发出后再补一条图片
- **搜索工具**（AI 调 `sticker_search` + `sticker_pick`）：`separate_after` 时先发 `caption` 文字，隔 `separate_send_gap_ms` 毫秒再发图片；`same_message` 时两者合并成一条

想两条消息之间停顿更自然就把 `separate_send_gap_ms` 调到 500~800；被平台风控或吞图时优先调大间隔。设为 `same_message` 则回到"文字+图一条"的旧观感。

## 打标速度与批量导入

一次导入 100 张时，实际瓶颈通常不在模型，而在四处：思考 token、原图 base64 体积、每张重建的 HTTPS 连接、以及被串起来的请求。本版都处理了，其中第一条是决定性的：

| 优化 | 效果 |
| --- | --- |
| `llm_reasoning_effort: low` | glm-5.3-flash 实测单张 **20.1s → 3.6s**（completion 488→78 token，reasoning 403→0），标注结果一致 |
| 打标前缩图到 896 | 392KB 图 → 157KB 上传体积 |
| 复用 HTTP 会话 | 不再每张重做 TCP + TLS 握手 |
| 输出字段 6→5，去掉 `intents`，`max_tokens` 1200→800 | 单张返回更快，且给思考型模型留够空间不截断 |
| 固定 worker 池 + 有界队列 | 限流时只设全局冷却，不再让 worker 抱着 sleep 占坑 |
| 索引写入合并成 1.5 秒一次 | 100 张完成时不会同步重写 100 次 json |

估算：`并发 ÷ (单张耗时 + 最小间隔)` 就是每秒吞吐。默认 2 并发、1 秒间隔、单张 3.6 秒时约 0.43 张/秒，**100 张 4 分钟左右**（改之前是 20 秒/张，同样配置要 17 分钟）。服务器扛得住的话把 `llm_concurrency` 调到 3~4 还能再快一倍，前提是别把服务商打成 429——面板顶部会实时显示「进行 / 排队 / 未完成 / 失败 / 上游冷却」。

中断也不怕：插件重启后 `initialize()` 会把 `pending` 的任务重新入队，不用一张张手动点重打标。

待审核里点「拒绝」= 直接删掉，不再留个 rejected 占地方。

- **拒绝即删除**：图片文件、索引记录、待打标队列一并清掉。以前只是标成 `rejected` 留在库里，不参与检索但也删不掉，翻列表时还老能看见

### v1.10.2
修「偷进来的图只有上面一截」，并给偷图加了刹车。

- **修半张图**：`aiohttp` 的 `StreamReader.read(n)` 语义是「最多 n 字节」，数据没全到齐时它先把手上那点返回。之前写成 `read(max_bytes + 1)`，实际每次只拿到第一个 chunk —— 正好 16384 字节，存进库就是只有上半截的破图（渐进式 JPEG 尤其明显）。改成 `iter_chunked()` 读到 EOF
- **存盘前校验完整性**：有 `Content-Length` 就对长度，没有就看尾部标记（JPEG 的 `FFD9` / PNG 的 `IEND` / GIF 的 `0x3B`）；对不上自动重下一次，两次都不完整就明确报「没下完整」，不再往库里塞半截图
- **修 `steal_max_mb` 形同虚设**：旧代码把「MB 数 × 1024 × 1024」的结果又拿去和 `32` 取最小值，等于上限恒定 32MB，填 1 也是 32MB
- **`steal_cooldown`**（默认 30 秒）：同一个会话两次偷之间要隔一会儿，防止被一张接一张地刷。同一条消息里连着偷几张（一口气发三张说都要）不算刷，不会被拦
- **`steal_daily_limit`**（默认 20 张）：每天偷多少张上限，按入库时间统计，满额当天不再收录，第二天自动恢复，重启也不会清零。填 0 = 不限制
- 冷却中 / 额度满时**不再给 AI 偷图提示**，免得它先问「要不要偷」再被工具打回，白烧一轮 token

### v1.9.0
主模型被限流时，不用干等了。

- **新增「候选打标模型」**（`llm_provider_pool`）：配置页里勾几个备用模型，按勾选顺序作为降级链。主模型 429/503/超时/返回坏 JSON 时自动换下一个，整条队列不会卡在一个限流的 key 上
  - 图片只读一次、只缩放一次、只 base64 一次，**换模型不重读磁盘**，所以配了候选也不会让正常情况变慢
  - 按模型记熔断：某个模型被限流后，后面排队的几百张会先挑没冷却的用，不会每张都先去撞一次 429
  - 按模型记 `reasoning_effort`：A 模型不认这个字段被 400 了，换到 B 模型照样带 low，不会连带退化成「始终思考」
  - 主模型没配也能跑：候选里有能用的就算就绪
  - 配置页是一个多选胶囊组（`✓ 已选` / `+ 未选`），点一下立即保存
- **「打标队列」页显示模型池**：主模型 + 候选一行胶囊，正在限流的标红并显示剩余冷却秒数，一眼看出要不要换模型
- 状态行与 `/sticker status` 的模型说明会带上候选数量：`自动 · glm-5.3-flash @ open.bigmodel.cn（+2 个候选）`
- **顺手修**：旧版遇到 500 之类的错误重试时，会把 `reasoning_effort` 一起摘掉（只有 400 才该摘），于是从第二张起悄悄退回「始终思考」的慢速模式。现在只在真被 400 拒绝时才摘，且只对那个模型生效

### v1.8.0
批量打标终于可以暂停了，API 也不用再填第二遍。

- **新增「打标队列」页**：进行中 / 排队中 / 本次已完成 / 失败 六个数字、进度条、**速度（张/秒）与预计剩余时间**（按最近 30 张的平均速度算，早期慢得不拖后腿）、进行中与排队中的逐条列表（各带已跑秒数 / 已等时长）、失败列表带错误原因
- **暂停 / 继续打标**：暂停只拦「下一张」，已经在飞的那几张会跑完 —— HTTP 请求硬中断会让那条永远卡在「打标中」。按暂停时刚取到手的任务会放回队尾。暂停状态只在内存里，重启插件自动恢复运行
- **清空待打标**：把还没开始的从队列撤掉、状态退回「未打标」，不动图片和已有标注
- **批量重试**：一键「重试全部失败」或「打标未打标的」
- **打标模型直接读 AstrBot**：新增 `llm_source`（自动 / 跟随 AstrBot / 手动填写）与 `llm_provider_id`。配置页里「AstrBot 提供商」是动态下拉，直接列出你在 AstrBot「服务提供商」里配好的模型（`模型名 — provider id`），选中即可，**不用再抄一遍 Base URL / Key / 模型名**
  - 「自动」= 手填三项填全了就用它们（老用户配置原样生效），缺了就跟随 AstrBot，所以**什么都不填也能直接用**
  - 只列 OpenAI 兼容的类型（anthropic / gemini / bedrock 这类接口形状不同，会被过滤掉，避免打标 404）
  - Key 只从 provider 实例内存里读，不会返回给前端；API 仍然由插件自己发，`reasoning_effort`、超时、并发照旧可控
  - 配置页提示行会显示「当前实际使用：自动 · glm-5.3-flash @ open.bigmodel.cn」，改完自动刷新
- **批量删除不用再滚回顶部**：勾选之后批量条**吸顶跟随**；已选中的卡片上，删除按钮直接变成「删除(N)」，点它就一次删掉这 N 张（点未选中的卡片仍是只删那一张）
- 库存页顶部的状态行改为直接显示实际模型、预计剩余时间与暂停状态；`/sticker status` 增加「打标模型」一行

### v1.6.2
工具返回的 token 开销可配。**工具结果会永久留在对话历史里，之后每一轮都要重新计费**，所以这一版按档位裁剪。

- **新增 `search_detail`（精简 / 标准 / 完整）**：精简只给「id + 名称 + 主情绪」，标准加 36 字画面描述，完整再加次情绪和置信度。`sticker_list` 也跟随同一档位（0 / 24 / 40 字描述）
- **`top_k` 默认 6 → 4**：4 条足够 AI 挑，多给的两条只是更贵
- **新增 `list_page_size`（默认 10）**：`sticker_list` 原固定每页 20 条
- 实测（44 张真实库存，单次调用）：`sticker_search` 665 → **318 token**（精简 4 条，省 52%）；`sticker_list` 1435 → **271 token**（精简 10 条，省 81%）
- 顺带说明：**快速通道不消耗检索 token**。它由 AI 直接输出 `<sticker>{"query":"..."}</sticker>`，本地检索、不产生工具返回，所以想省 token 应该多用快速通道、少调 `sticker_search`

### v1.6.1
修掉「画面型查询发不出图」这个 1.6.0 引入的退化。

- **修复无空格长串分词**：`蓝发女仆眨眼` 这种没打空格的 query 之前会被当成一个整词，跟每个单个标签做包含匹配都只有 0.9 分（1.41，低于 1.5 门槛，永远发不出图）。现在按**库存标签词表**做正向最大匹配切词（`蓝发女仆` + `眨眼`），词典来自库存本身所以切出来的词一定可能被命中；必须切出 ≥2 个词才采用，切不动就原样保留。实测同一查询 1.41 → 2.55，命中「眨眼竖大拇指」那张
- **新增多关键词覆盖加成**：一张图同时覆盖 query 的多个画面词时每个 +0.45（封顶 2 个）。按 keywords 计数而非 tags 计数，所以图里标签多不会自动加分，不会退回旧版「标签越多越容易被选中」
- **检索提速**：`_quality` 增加「无共同字直接判 0」预筛（与 difflib 结果等价，纯省算），`tags` 的最佳命中与覆盖数合并成一次遍历。500 张库单次检索 34~65ms → 3~9ms
- 标签词表加缓存，索引落盘时失效

### v1.6.0
打标准确率与检索质量重做，老库不需要重新打标，`index.json` 结构向后兼容。

- **打标提示词改为受控词表**：情绪只能从固定词表里选，「主情绪一个 + 次情绪至多一个 + 置信度」；禁止近义词堆叠（无语/沉默/嫌弃 只留最贴的一个）；去掉纯靠猜的 `intents` 字段；`tags` 只能写看得见的画面元素，情绪词混进去会被服务端剔除
- **低置信自动收敛**：`confidence < 0.6` 时只保留主情绪，丢弃次情绪
- **检索计分重写**：每字段取最佳命中后加权，不再把「精确 / 整句子串 / 模糊」三层相加（旧版一个错标签能拿 6.25 分）；主情绪权重 3.0、名称从 4.0 降到 0.5；取消中文 2-gram 拆词，改双向包含匹配；模糊阈值 0.4→0.62（「沉思/沉默」不再混为一谈）
- **自动发图加闸门**：低于门槛或领先不足就只发文字，不再「任意命中就发」；门槛按配图频档自动放宽，选「每条都发」时只拦真正毫无关系的候选
- **危险标签拦截**：`blocked_tags` 命中的图不会被自动发出（AI 检索词本身提到才放行），防止「病娇持刀」被当成「呆萌」发出去
- **同分随机**：强命中且分数接近时随机挑一张，不再永远发同一张
- **手改保护**：面板改过的字段记进 `human`，重打标只补没改过的，不再一键冲掉手动清理的成果；卡片上显示主情绪 / 置信度 / 「手改」标记
- **打标队列重写**：每张一个 task 改为固定 worker 池 + 有界队列，限流时不再抱 sleep 占坑；复用 HTTP 会话、打标前缩图、`max_tokens` 800；索引写入合并；重启后自动续跑 pending
- **打标提速 5.6 倍**：新增 `llm_reasoning_effort`（默认 low）。glm-5.x 这类「始终思考」的模型默认烧 400+ reasoning token，实测单张 20.1s → 3.6s，标注结果一致；接口不认这个参数时自动降级重试
- **修 bug**：上传时填了描述会跳过打标导致该图几乎搜不到；`_api_upload` 每张都重新解析一次表单；大文件读写阻塞事件循环（100 张上传时面板像卡死）
- 面板顶部显示打标队列进度并在有任务时自动刷新；`/sticker status` 增加队列与「上次为什么没发图」的诊断
